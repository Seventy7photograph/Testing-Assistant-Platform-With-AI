## 一、结论

v3.0.0 已完成合并版开发，以下能力在本地真实服务、临时存储和离线 fixture 下通过：

- 项目仓储分区、可选 API Key 鉴权、配额与项目审计
- Jira / 禅道 REST 适配器、需求幂等拉取、用例回写、外部状态回读
- 按任务、成本与质量路由模型，并输出可追溯理由
- 仅执行已校验接口用例的受控 HTTP 执行器
- Job、Schedule、AgentRun、ToolCall 数据模型与审计
- 项目级 SQLite FTS5 中文知识检索、删除生命周期与跨项目隔离
- 全局只读助手、确定性当前事实、知识引用、无依据拒答与注入防护
- 独立项目、外部连接、知识索引、运行任务页与全站右侧助手
- 独立页面信息架构与全站右侧 RAG 助手
- Paper & Ink Workbench 三色视觉系统与页面解释性文案清理

“有条件”仅指没有可用真实 Jira / 禅道沙箱：本次真实验证的是适配器 HTTP 契约
（MockTransport）和 fixture 端到端链路。真实实例联调需在部署环境补一次只读健康检查和
单条需求同步见证。

## 五、验收中发现并修复的问题

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 项目知识删除路径二次拼接 `projects/<id>` | 索引写入和删除落在不同 SQLite 文件 | 识别已分区的 Settings，统一到项目知识库路径 |
| SQLite Cursor 误用 `.first()` | 知识 upsert/删除 500 | 改为 `.fetchone()` |
| 文档配额检查使用项目级 Settings 查全局项目注册表 | 项目上传误报 404 | 分离 `platform_settings` 与项目文件 `settings` |
| 上传文件仍落全局 `storage/uploads` | 记录隔离但物理文件未分区 | 文档、图片、删除校验全部切换项目路径 |
| 报告 SQLite 路径未随项目切换 | 报告存档跨项目共用 | 按当前项目选择 data 目录，并维护按路径初始化集合 |
| 新增助手按钮使 390px 顶栏横向溢出 3px | 移动端横向滚动 | 640px 以下隐藏非必要顶栏控件 |
| 首次路由切换立即检查吸底栏存在时序竞争 | 冒烟偶发误报 | 等待目标 URL 和路由过渡完成后再断言 |

## 六、安全与隐私检查

- 项目身份只从中间件验证后的 ContextVar 进入仓储与知识库。
- 知识、Job、ToolCall、审计查询均带项目边界。
- 外部集成 Token 只从环境变量读取，不进入请求 fixture、文档或 Git。
- 受控执行不执行任意 Python、shell、子进程、`eval` 或 `exec`。
- 执行环境变量只在内存中使用，不写入 Job/TestRun/事件/日志。
- 知识文档、外部需求和用户输入按不可信数据处理；注入内容不能改变工具策略。
- 无来源知识回答拒答，当前状态使用确定性工具。
